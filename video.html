SilentTip — 90-second demo

A Nostr creator publishes one reusable silent-payment identity; every tip to it lands at a fresh, unlinked on-chain address. Everything below runs on Bitcoin signet — test coins only.

What you're seeing

  1. Receive — generate a silent-payment identity (scan + spend keys, browser-side) and publish it as a signed Nostr event (kind 30078, d=silenttip) that public relays accept.
  2. Tip — paste the creator's npub; the app resolves the binding live, verifies the schnorr signature, and derives the BIP-352 output key (P = B_spend + hash(input_hash·a·B_scan‖k)·G).
  3. What the chain sees — inspect any real signet transaction's outputs: a silent tip is just another x-only taproot key — nothing links it to the reusable address. (The tx shown is an unrelated signet tx, presented as what a tip looks like, not claimed to be one.)
  4. Scan — the receiver's scan key walks signet blocks via Esplora and recomputes candidate outputs; only their keys reveal which outputs are theirs.

Why this is private

Address reuse is how chain analysis clusters a creator's income. Silent payments fix it at the protocol level: the sender does the ECDH work off-chain, so each tip creates a brand-new taproot output. The chain never sees the creator's published address — there is nothing to cluster.

Broadcast proof on local regtest (24 s): the same code path — build, broadcast, mine, receiver scan — runs end to end on a disposable regtest chain below. On public signet, broadcasting is still blocked only by captcha/login-gated faucets — see docs/evidence.md for the exact, verifiable record of what has and has not been broadcast. The regtest fixture publishes its disposable receiver keys, so the Nostr-bound address shown in that proof must never be used for a funded Signet tip.
