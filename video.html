SilentTip — demo video

A Nostr creator publishes one reusable silent-payment identity; every tip to it lands at a fresh on-chain output observers cannot link back to it. Everything below runs on Bitcoin signet — test coins only.

This walkthrough was re-captured after earlier demo identities were retired: only the promoted demo identity appears, the receiver seed is never shown (the restore field is password-masked and the rendered seed element is blanked before it can paint), and every exported frame was OCR-scanned for leaked keys before publishing. Sender inputs, change, amounts and timing stay visible.

What you're seeing

  1. Receive — restore the demo silent-payment identity (scan + spend keys, browser-side; the seed never appears). Its tsp1 address was published as a signed Nostr event (kind 30078, d=silenttip) that public relays accepted.
  2. Tip — paste the creator's npub; the app resolves the binding live, verifies the schnorr signature, and shows the bound tsp1 (event 5a9f1252…). A throwaway sender wallet is generated and the broadcast button honestly reports no UTXOs — the demo wallet is unfunded, so nothing is claimed on-chain.
  3. What the chain sees — inspect any real signet transaction's outputs: a silent tip is just another x-only taproot key — nothing links it to the reusable address. (The tx shown is an unrelated signet tx, presented as what a tip looks like, not claimed to be one.)
  4. Scan — the receiver's scan key walks signet blocks via Esplora and recomputes candidate outputs; only their keys reveal which outputs are theirs.

Why this is private

Address reuse is how chain analysis clusters a creator's income. Silent payments fix it at the protocol level: the sender does the ECDH work off-chain, so each tip creates a brand-new taproot output. The chain never sees the creator's published address, so tips cannot be clustered to it by address reuse. (Honest limits: sender inputs, change, amounts and timing stay visible, and spending several tips together can link those outputs to each other.)

Broadcast proof on local regtest: a real BIP-352 tip to a dedicated regtest-only receiver — built by the repo's own transaction builder, broadcast, mined, and found by the repo's own receiver scan — runs end to end on a disposable regtest chain below (the transaction builder and scanner are the same code the app uses; UTXO discovery, broadcast transport and block fetching differ). On public signet, broadcasting is still blocked only by captcha/login-gated faucets — see docs/evidence.md for the exact, verifiable record of what has and has not been broadcast. The fixture's regtest-only receiver keys are public — it is never bound to Nostr and never used on signet; promoted identities are always fresh and private.
